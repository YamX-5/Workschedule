# Yami Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the real Yami app (Android + installable PWA) with the full System loop running on real saved data: quests, Judgment at Fajr, Honor, levels, Protocol settings, Gates, Log out, and the Limit → Reserve → Sealed flow in simulate mode.

**Architecture:** One Expo (React Native + TypeScript) codebase in `yami/`, using Expo Router for screens. All game rules live in pure TypeScript under `yami/src/domain/` with no React or I/O; they are fully unit-tested and are the single source of truth. A Zustand store persisted through AsyncStorage holds one serialisable `Profile` (versioned, for future accounts and cloud sync). Screens read the store and call domain functions. The 3D world and the native Android lock come in Plans 2 and 3; this plan leaves a `HeroStage` slot and a `ShieldBridge` interface for them.

**Tech Stack:** Expo SDK (latest stable from `create-expo-app@latest`; record the resolved version in `yami/README.md`), Expo Router, TypeScript strict, Zustand + `@react-native-async-storage/async-storage`, `react-native-reanimated`, `react-native-gesture-handler`, `react-native-svg`, `adhan`, `expo-notifications`, `expo-haptics`, `@expo-google-fonts/michroma`, `@expo-google-fonts/chakra-petch`, Jest via `jest-expo`, `@testing-library/react-native`.

**Spec:** `docs/superpowers/specs/2026-11-08-yami-design.md` (sections 4, 9, 10, 11 are the binding ones). Visual reference: `mockups/d-system.html` (open it; copy look, copy text and motion from it).

## Global Constraints

- App name **Yami** (闇). Palette is exactly 4 colours: white `#F2F0F7`, black `#030308`, dark purple `#2A1252` (highlight `#6B3BD9`), light blue `#8FDCFF`. No other hues; semantic states use these 4 only.
- Fonts: **Michroma** for display and numbers, **Chakra Petch** for everything else. Minimum text size 11.
- **No emojis anywhere in the product.**
- Motion: ease-out / spring only (`cubic-bezier(.22,1,.36,1)` equivalent), UI transitions ≤ 300 ms, press scale 0.97, never animate from scale 0. Respect reduce-motion (`AccessibilityInfo.isReduceMotionEnabled`).
- The day resets at **Fajr**, not midnight.
- Default protocol values: phone cap **120 min**; Necessity Reserve **30 min**; wind-down **22:30**; sleep target **23:00**; Fajr alarm **05:30**; work windows **13:00–13:20** and **18:00–18:20**.
- Friction tiers: used < cap − 30 → **5 s**; used < cap − 15 → **15 s**; used < cap → **30 s**; used ≥ cap → limit.
- Judgment multipliers on the unreported penalty: Mercy **1×**, Balanced **1.5×**, Ruthless **2×**. Confessed: **+2 Honor**, 0 XP lost (Ruthless: −0.25 × xp). Late report: **50%** XP, Honor unchanged. Unreported: −mult × xp, **−5 Honor**, **+10 min** corruption carried into the next day.
- Honor is clamped to **0–100**, and new profiles start at **50**.
- Never miss twice: the same quest missed (Confessed or Unreported) on 2 consecutive days applies **Fractured**: that quest's stat earns **×0.8** XP for the next day.
- FALL resets level, XP, streak and quest history to Day 1, and keeps Honor, `fallRecord`, `scars`, protocol and quests.
- Always-open apps can never be Sealed: Phone, Messages, Maps, Quran, Bank.
- Persisted state carries `schemaVersion` (starts at **1**). Every load runs `migrate()`.
- Web build: no native-only module may be imported unguarded; use a `.web.ts` stub or `Platform.OS` check.

## Review Focus

1. **Activity between midnight and Fajr** (e.g. a report at 01:30) belongs to the *previous* day. Tested in Task 2.
2. **The cap is lowered mid-day below the minutes already used** → the state goes straight to `limit` (or `reserve`/`sealed`), never to a negative "left". Tested in Task 3.
3. **A quest is edited or deleted after it was reported today** → today's report stays attached to the quest id; deleting a quest drops it from tonight's Judgment without penalty. Tested in Task 5.
4. **Old or partial saved data after an app update** (missing fields, older `schemaVersion`) → `migrate()` fills defaults and never crashes. Tested in Task 7.
5. **The device clock is moved forward to skip to "tomorrow"** → in Core, Judgment runs only once per `dayKey` and never twice for the same day; full clock anti-cheat is Plan 2. Tested in Task 5.
